# 19. 前端架构中，为什么 Git 提交时可以触发校验？

**答案：**

**Git Hooks 机制：**

Git 提交时触发校验是通过 Git Hooks 实现的，Git Hooks 是 Git 在特定事件发生时自动执行的脚本。

**常用 Git Hooks：**

1. **pre-commit**：在 `git commit` 执行前触发
2. **commit-msg**：在提交信息编辑后触发
3. **pre-push**：在 `git push` 执行前触发

**实现方式：**

1. **使用 Husky**
```bash
npm install husky --save-dev
npx husky install
npx husky add .husky/pre-commit "npm test"
```

2. **常用校验工具：**
   - **ESLint**：代码质量检查
   - **Prettier**：代码格式化
   - **Commitlint**：提交信息规范
   - **lint-staged**：只检查暂存文件

**工作原理：**

1. 用户执行 `git commit`
2. Git 触发 `pre-commit` hook
3. 执行 lint-staged，检查暂存文件
4. 执行 ESLint、Prettier 等校验
5. 如果校验失败，阻止提交
6. 如果校验通过，进入 commit-msg hook
7. 检查提交信息格式
8. 所有检查通过后，完成提交

**为什么需要提交前校验：**

1. **保证代码质量**：防止低质量代码进入仓库
2. **统一代码风格**：保持团队代码风格一致
3. **提前发现问题**：在 CI 之前发现并修复问题
4. **规范提交信息**：便于生成 CHANGELOG 和代码审查
5. **提高效率**：减少 CI 失败率，节省时间
